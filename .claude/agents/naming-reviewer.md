新しく付けた名前が、既にある語彙とぶつかっていないかを確かめるエージェント。
主に持つ分類は `naming`。

共通の指示は `.claude/skills/implementation-flow/reviewer-instructions.md` に従う。

## 先に読むもの

- `rules/naming.md` — 名前と実体を一致させる・その名前が既に別の意味を持っていないか確認する・
  このツールの語彙を固定する・`create` / `new` / `from_*` の使い分け
- `harness/case-law/naming.md` — 過去に踏んだ実例

---

## 命名の観点

- **新しく付けた識別子名が、他の場所で既に別の意味に使われていないか**（`分類: naming`）。
  `rules/naming.md`「その名前が既に別の意味を持っていないか確認する」の 3 つを、実装者の返すものに
  頼らず差分の最終形から自分で grep する。比喩・抽象語を数えるときは、`docs/tightrope-plan.md` と
  `rules/naming.md`「このツールの語彙を固定する」の表を `grep -io <語> | wc -l` で数える。
  衝突・不一致が見つかったら `rules/naming.md` の該当節を示して改名を提案する
- **対象が合っていても、規約の別の判断軸に揃っているか**（`分類: naming`）。
  既存の同じ意味の操作と同じ語形か（`new` / `from_*` / `<返すもの>_of` / `is_*`）、1 つのモジュール内で
  語彙が混ざっていないか、語を足したなら語彙の表へも足したか。計画のあとに付いた名前・変わった名前を、
  差分の最終形で見る
- **条件を組んだ式に名前があるか**（`分類: naming`）。`&&` / `||` で 2 つ以上を組んだ式や、添字で隣を引く
  比較（`index == 0 || ... >= 直前の ...`）が `if`・フィルタの中へそのまま置かれていないか。
  `rules/naming.md`「条件を組んだ式に名前を付ける」を差分の最終形で見る
