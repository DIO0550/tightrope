# tightrope report - 距離と変動性仕様（バックエンド）

> **機能**: [tightrope report（MVP）](./index.md)

## 概要

依存 1 本について、`from` と `to` の位置関係から距離を、`to` の git の変更回数から変動性を測る。

## 距離

| 距離 | 条件 |
|:-----|:-----|
| `same-directory` | `from` と `to` が同じディレクトリ |
| `other-directory` | ディレクトリが違い、package が同じ |
| `other-package` | package が違う（monorepo / workspace） |

近い順に same-directory < other-directory < other-package。

| ID | ルール | 条件 | 振る舞い |
|:---|:-------|:-----|:---------|
| DIS-001 | package | — | そのファイルから上へ辿って最初に見つかる `package.json` のディレクトリ。走査の根の外まで辿る |
| DIS-002 | package が見つからない | ファイルシステムの根まで `package.json` が無い | 走査の根を package とみなす（両側とも見つからなければ同じ package） |

- module がファイルなので「同一ファイル」の段は無い
- 「別チーム」の段は CODEOWNERS を読むときに足す（まだ動かない選択肢を置かない）

**Why（DIS-002 で取れなかったにしない）**: package の有無は距離の答えに効かない欠けではなく、「package を分けていない」という答えそのもの。

## 変動性

| ID | ルール | 条件 | 振る舞い |
|:---|:-------|:-----|:---------|
| VOL-001 | 測る相手 | — | **依存先（`to`）のファイル**の変更回数。依存される側が変わると、依存する側に変更が波及するため |
| VOL-002 | 数え方 | — | 期間内に、そのファイルを変えたコミットの数（マージコミットは数えない） |
| VOL-003 | 期間 | — | 実行した時点から `volatility_window_days`（既定 180 日）遡る |
| VOL-004 | git の呼び方 | — | 走査の根で `git log` を **1 回だけ**呼び、出力からファイルごとの回数を数える。ファイルごとに呼ばない |
| VOL-005 | リネーム | — | 追わない。リネーム前の履歴は数えない |
| VOL-006 | 期間内に 1 回も変わっていない | 履歴はあるが期間内に変更が無い | 0 回（取れなかったではない） |

呼ぶコマンドの形:

```
git -C <dir> log --since=<N>.days --no-merges --name-only --format=<コミットの区切り>
```

出力を受け取ってから先（区切りとパスを読んで回数にする）は純粋な関数にする。パスはリポジトリの根からの相対で出るので、走査の根からの相対に直す。

### 取れなかったとき

すべて「取れなかった」として理由ごとに出す。0 で埋めない。

| 理由 | 発生条件 |
|:-----|:---------|
| `not-a-git-repository` | 走査の根が git のリポジトリの中に無い |
| `git-unavailable` | `git` が無い・起動に失敗した |
| `git-failed` | `git log` が 0 以外で終わった（浅い clone で履歴が無いなど） |
| `untracked` | そのファイルが git に追跡されていない（作業ツリーにだけある） |

- 理由はファイルごとに持つ。リポジトリ全体の理由（上の 3 つ）は全ファイルに同じ理由が付く
- 実行時刻に依存するので、`coupling.json` には期間と、数えた時点のコミット（`HEAD`）を残す（[coupling-json-spec.md](./coupling-json-spec.md)）

## 制限事項

- co-change（一緒に変わるファイル）は出さない
- 変更の大きさ（追加・削除行数）は見ない。回数だけ
- サブモジュールの中のファイルの履歴は数えない
