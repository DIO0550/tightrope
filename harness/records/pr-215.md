# PR #215 単体テストを tests.rs に置く規約にし、同じファイルのテストを pre-push で落とす

- マージ日: 2026-11-20
- 関連 Issue: #214
- 差分規模: 10 ファイル / +207 -51

## ゴールと結果

単体テストを実装と同じファイルの `mod tests { .. }` に書かず、`mod tests;` が指す `tests.rs` に置く規約にする（利用者の希望）。達成。`rules/testing.md` に置き場所と逸脱の Why を書き（常時ロード 663 行のまま）、`harness/githooks/lib/test-placement.sh` を pre-push（CI の harness ジョブ）へ配線し、main の `src/strength.rs` のテストを移した。開いていた #209〜#212 のテストは、main との衝突を解いた回にそれぞれのブランチで移した。

## 指摘

### 1. 規約を検査しないまま、refactor.md の `git diff -- src` を外していた

- 分類: `harness`
- 出どころ: `レビュー（harness-reviewer）`
- 形の名前: `tooling-rule-scope-gap`
- 内容: 当初は検査をスコープ外にしていたが、refactor.md から `src/` の hunk を読む段を外したため、規約に反して同じファイルに書かれたテストの書き換えがどのコマンドにも出なくなっていた。一時リポジトリで再現された。検査をこの PR に入れた。
- 既存ルール: AGENTS.md「強制力の序列」（ツールで落とせるものは規約の文に留めない）

### 2. 規約の文と pathspec が、クレートのルートと `tests/` の子に届いていなかった

- 分類: `harness`
- 出どころ: `レビュー（harness-reviewer）`
- 形の名前: `tool-behavior-unverified`
- 形の名前: `rules-consistency`
- 内容: `src/<名前>/tests.rs` と書くと lib.rs のテストが `src/lib/tests.rs` と読める（正しくは `src/tests.rs`）。`src/**/tests.rs` は `src/x/tests/helpers.rs` に当たらない。文を「`mod tests;` が指す `tests.rs`」にし、pathspec に `src/**/tests/**` を足した。
- 既存ルール: rules/coding.md「外部の挙動は動かして確かめる」

### 3. rules/testing.md の節の参照を `…` で切り、Why を箇条の中に続けて書いていた

- 分類: `harness`
- 出どころ: `レビュー（harness-reviewer）`
- 内容: 他の `rules/` は節の名前をそのまま書き、`**Why**:` は独立した段落にしている。前提の文の重複した命名の例を詰めて行数を空け、参照を消して Why を段落に出した。
- 既存ルール: なし

### 4. 第 1 工程で `tests.rs` を新しく作るときの `mod tests;` の 2 行の扱いが書かれていなかった

- 分類: `harness`
- 出どころ: `レビュー（harness-reviewer）`
- 内容: 第 1 工程の `git status --porcelain` の突き合わせをテストのファイルだけに狭めるので、実装のファイルへ足す 2 行が「実装を触った」と読まれる。テストの配線として含める旨を SKILL.md に 1 行足した。
- 既存ルール: なし

### 5. 検査がコメント・文字列の中の `#[test]` を拾い、`#[cfg_attr(test, test)]` を見落としていた

- 分類: `harness`
- 出どころ: `レビュー（bot）`

- 既存ルール: rules/coding.md「列挙で判定を組むときは、漏れの倒れる向きを選ぶ」

### 6. 走査の失敗を「違反なし」の exit 0 にしていた

- 分類: `harness`
- 出どころ: `レビュー（bot）`

- 既存ルール: rules/coding.md「不在は `Option`、失敗は `Result`」（失敗を握りつぶして既定値へフォールバックしない）
