# PR #262 I/O を持たない crate で I/O の API と mod.rs を clippy で落とす

- マージ日: 2026-11-24
- 関連 Issue: #255
- 差分規模: 9 ファイル / +604 -6

## ゴールと結果

ゴール: I/O を持たない crate(domain / presentation)で `std::fs` の読み書きと子プロセスの起動を書くと、根の clippy が落ちる。`mod.rs` を置いても落ちる。infrastructure と tightrope は今のまま通る。

達成。crate ごとの clippy.toml(`disallowed-methods` 34 件・`disallowed-types` 11 件)と `mod_module_files = "deny"` を置き、判定表 `clippy-config-cases.sh`(115 件)が設定の漏れ・余分・写し漏れを落とす。Red は判定表だけが NG 98 で落ち、Green で pre-push 35 件と CI がすべて通った。守れていない穴(unwrap の deny が効いているか)は #254 へ回した。
